# 圍棋 Weiqi

一款以繁體中文呈現、可在電腦、平板與手機瀏覽器遊玩的圍棋遊戲。你可以挑戰不同等級的電腦，也可以和朋友在同一台裝置上對弈。

## 開始遊戲

前往 GitHub Pages 網站即可遊玩：

- **遊戲專案：** https://github.com/s230127-lab/weiqi_online
- **遊戲程式：** [index.html](./index.html)
- **KataGo 模型：** [models/katago.onnx](./models/katago.onnx)

也可以自行部署本專案。將整個專案（包括 `models/` 資料夾）放在支援靜態網站的主機上，再透過瀏覽器開啟網站即可。請不要直接以檔案方式開啟 `index.html`（`file://`）；模型載入需要網站伺服器提供檔案。

## 遊戲功能

- **三種對弈模式：** 人機對弈、雙人對弈、面對面對弈。
- **六種電腦等級：** 從入門到 KataGo 與 Leela Zero 模型。
- **三種棋盤尺寸：** 9 路、13 路、19 路。
- **黑白棋色選擇：** 人機模式可選擇執黑或執白。
- **對局操作：** 悔棋、虛手、認輸、新遊戲。
- **終局與計分：** 可手動或自動標記死子，再依中國規則數子。
- **自動重新開局：** 可選擇對局結束後自動開始下一局。
- **適合觸控操作：** 棋盤會依螢幕尺寸調整，支援滑鼠、觸控及平板操作。

## 對弈模式

| 模式 | 說明 |
| --- | --- |
| 人機對弈 | 與電腦對弈，可選擇電腦等級及自己使用黑棋或白棋。 |
| 雙人對弈 | 兩位玩家輪流在同一棋盤上落子。 |
| 面對面對弈 | 將裝置平放在兩位玩家中間；黑方坐在裝置下方，白方坐在上方。雙方各自的資訊和操作按鈕會朝向自己。 |

面對面模式適合共用一台平板或筆電。為避免誤觸，認輸按鈕需要連續確認兩次。

## 電腦等級

| 等級 | 名稱 | 下棋方式 |
| --- | --- | --- |
| Lv 1 | 入門 | 隨機選擇合法棋步。 |
| Lv 2 | 初級 | 使用基本戰術判斷，例如提子、叫吃及避免自打吃。 |
| Lv 3 | 中級 | 加入蒙地卡羅模擬，評估候選棋步。 |
| Lv 4 | 高級 | 使用更多模擬思考，通常比 Lv 3 花費更長時間。 |
| Lv 5 | KataGo AI | 使用專案內的 ONNX 模型進行推論。 |
| Lv 6 | Leela Zero（舊版 WebGL） | 使用瀏覽器版 WebAssembly／WebGL 引擎與神經網路。 |

電腦在瀏覽器內運算，不需要連接遠端 AI 推論服務。不同裝置的運算效能會影響思考時間；目前的電腦策略在 9 路棋盤上較能發揮。

## KataGo AI（Lv 5）

本專案已將 KataGo ONNX 模型放在：

```text
models/katago.onnx
```

選擇人機模式並使用 **Lv 5** 時，遊戲才會載入模型。其他等級不需要下載這個模型。

- **首次使用：** 瀏覽器會從本專案載入約 75 MB 的模型資料，因此需要網路連線並等待下載完成。
- **再次使用：** 瀏覽器會嘗試透過 Cache Storage 快取模型；若快取仍可用，之後可能不必重新下載。
- **本機推論：** 模型載入後，棋步推論由你的裝置在瀏覽器內執行，不會把棋局送到遠端 AI 推論 API。
- **執行環境：** 遊戲使用 ONNX Runtime Web。第一次使用 Lv 5 時，頁面也會從 jsDelivr 載入對應的 ONNX Runtime Web 程式庫，因此仍需要網路連線。
- **Kaya 風格 MCTS 局面分析：** 按「分析目前局面」後，使用本機 KataGo ONNX 模型進行 PUCT 蒙地卡羅樹搜索，顯示候選著手、搜索訪問數、黑方勝率、目數估計，以及主要候選著手的後續主變化（PV）。
- **搜索深度設定：** 每個局面可選 12、24、48 或 96 次搜索訪問。增加訪問數通常會增加分析時間與裝置負擔。
- **整盤逐手分析：** 可重播目前棋譜，逐一分析每手之前的局面，對照實際著手與搜索首選，顯示估計勝率變化及失誤幅度。這些分類依有限訪問數的模型估算，僅供參考。
- **分析圖表：** 整盤分析完成或進行中，會顯示黑方估計勝率走勢與逐手摘要。
- **領地熱圖：** 只有在目前 ONNX 模型確實提供 KataGo ownership 輸出時才可啟用；若模型沒有此輸出，介面會說明無法顯示，不會以其他估算冒充模型領地預測。
- **本機運算：** 分析沿用本專案的 `models/katago.onnx` 與 ONNX Runtime Web，棋局不會送往遠端 AI 推論 API。第一次分析仍需下載約 75 MB 模型資料。
- **相容性說明：** 這是把 Kaya 的 KataGo ONNX / PUCT 分析概念整合到本專案單頁遊戲，不是直接嵌入完整 Kaya 應用程式；未包含 Kaya 所有設定、SGF 分析資料格式或完整分析樹瀏覽器。

## Leela Zero（Lv 6）

Lv 6 使用 [NTT123/leela-zero 的瀏覽器版移植](https://github.com/NTT123/leela-zero/tree/565ae3380946546504bb38c67a714b6c70300a23/src/docs)。這是 2017 年的舊版 WebGL／WebAssembly 示範，不是最新 Leela Zero 桌面引擎。原始專案的瀏覽器示範資訊可參閱 [Neural GO](https://ntt123.github.io/leela-zero/)。

- **首次使用：** 網頁會載入 `leela-engine.html`，再從固定版本的 jsDelivr CDN 取得引擎程式、WebAssembly 記憶體初始化檔與神經網路資料。請保持網路連線。
- **本機運算：** 載入後，神經網路推論透過瀏覽器的 WebGL 執行，Leela Zero 引擎以 WebAssembly 執行；遊戲棋盤與落子紀錄會傳給本機 iframe，不會呼叫遠端 AI 推論 API。
- **瀏覽器需求：** 需要支援 WebGL 的瀏覽器。若 WebGL 或 CDN 載入失敗，Lv 6 會顯示錯誤，不會假裝成 KataGo 或靜默切換模型。
- **版本限制：** 這是歷史示範版本，可能不適用於部分較新的瀏覽器或裝置；其實際棋力也取決於隨附的舊網路權重。
- **授權：** Leela Zero 原始程式採 GPL-3.0；請參閱 [上游授權文件](https://github.com/NTT123/leela-zero/blob/565ae3380946546504bb38c67a714b6c70300a23/COPYING)。相關瀏覽器移植與模型檔案的權利聲明以原始專案為準。

## 基本規則

1. 黑方先行，之後雙方輪流下一子；每回合可在棋盤任一合法交叉點落子。
2. 棋子相連形成棋塊；棋塊相鄰的空交叉點稱為「氣」。棋塊沒有任何氣時，便會被提走。
3. 落子後若自己的棋塊沒有氣，而且沒有因此提走對方棋子，該步就是自殺手，不能下。
4. 遊戲禁止全局同形：不能讓棋盤重現之前出現過的局面。
5. 雙方連續虛手即進入終局。
6. 終局時，雙方確認並標記死子，再進行數子。可以逐一點選棋塊標記，也可以使用「自動標記死子」功能；自動判定結果仍建議由雙方確認。

### 計分方式

本遊戲採用**中國規則的數子法**：計算棋盤上存活的棋子，以及由該方圍住的空點。

- 13 路及 19 路棋盤：黑方貼 **7.5 子**（3 又 3/4 子）。
- 9 路棋盤：本遊戲設定黑方貼 **7 子**（3 又 1/2 子）。

中國規則沒有特別規定 9 路棋盤的貼目數，因此本遊戲為 9 路棋盤採用 7 子貼目。

## 操作說明

- **落子：** 點擊或觸控棋盤上的交叉點。
- **悔棋：** 按「悔棋」返回之前的局面。
- **虛手：** 按「虛手」跳過這一回合。
- **認輸：** 按「認輸」結束對局；面對面模式需要再次確認。
- **數子：** 雙方連續虛手後，標記死子並按「數子」計算結果。
- **新遊戲：** 按「新遊戲」，或更改模式、棋盤尺寸、棋色及電腦等級以重新開始。

## 歡迎頁、英文介面與排行榜

開啟網站會先看到歡迎頁。按「開始遊戲」後會先顯示規則，閱讀後再按「開始對弈」。右上方可在繁體中文與 English 之間切換；語言選擇會保存在此瀏覽器。

排行榜使用 Google 登入與 Firebase Authentication / Cloud Firestore。未設定 Firebase 時，遊戲本身仍可遊玩，但登入、保存成績與排行榜不會運作。請依照以下步驟啟用：

1. 在 [Firebase Console](https://console.firebase.google.com/) 建立 Firebase 專案，並新增一個 Web App。
2. 在 **Authentication → Sign-in method** 啟用 **Google** 登入。
3. 在 **Firestore Database** 建立資料庫。
4. 將 Web App 的設定值（apiKey、authDomain、projectId、appId）填入 `index.html` 中的 `FIREBASE_CONFIG`。這些是瀏覽器端公開設定，不是 Admin SDK 私密金鑰；切勿把服務帳戶私密金鑰放進網頁。
5. 在 Firebase Authentication 的 **Authorized domains** 加入 GitHub Pages 網域（例如 `s230127-lab.github.io`），以及你實際使用的自訂網域。
6. 將本專案的 `firestore.rules` 發佈到 Firebase Firestore Rules。

### 成績與排名

- 必須先使用 Google 登入，對局結果才會寫入排行榜；未登入時，結果會暫存在目前頁面的記憶體中，登入後會嘗試補存。
- 人機模式以你選擇的黑棋或白棋計算勝負。雙人／面對面模式可選擇以哪一方作為登入玩家。
- 勝局 3 分、和局 1 分、敗局 0 分；排行榜顯示前 10 名，按積分、勝局數及勝率排序。
- Firestore 規則限制使用者只能更新自己的排名文件，並要求每次更新恰好新增一局及對應積分。
- 這是休閒排行榜，不是防作弊競技伺服器：目前遊戲在瀏覽器本機運算，伺服器不會重新驗證完整棋譜，因此使用者仍可能透過修改瀏覽器程式偽造成績。正式競技用途應增加伺服器端棋譜驗證。

## 技術資訊

- 單頁網頁應用程式，主要遊戲程式寫在 `index.html`。
- 使用 HTML Canvas 繪製棋盤與棋子。
- KataGo 模型格式為 ONNX，由 ONNX Runtime Web 在瀏覽器執行。
- Lv 1–6 的遊戲與 AI 推論不需要自建後端或 AI 推論 API 金鑰；Google 登入及排行榜需要設定 Firebase。
- Lv 1–4 的電腦策略在瀏覽器內執行；Lv 5 使用 KataGo ONNX；Lv 6 使用舊版 Leela Zero WebAssembly／WebGL 瀏覽器移植。
